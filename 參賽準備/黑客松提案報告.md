# SQL 變更影響評估 Copilot 提案報告

## 提案摘要

本提案以 SQL SPA Tools 與 Microsoft 365 Copilot Chat，建立 SQL 變更影響評估的參賽原型。SQL SPA Tools 在使用者瀏覽器中比對 SQL 版本並分析欄位血緣；使用者檢查摘要後，再將不含原始 SQL 的合成資料 JSON 上傳至 Copilot Chat，由 Copilot 整理影響說明及人工檢核清單。原型已具備摘要預覽、明確下載確認、可重現的合成案例及解析警告案例。目前只完成個人帳戶臨時聊天的合成 JSON 文字探索性演練；銀行核准租用戶、檔案上傳與效益數據仍待確認。競賽規則與銀行資料治理要求也待主辦單位及治理單位確認，因此本報告不宣稱已驗證的節省率、Copilot 準確率或正式環境適用性。

## 問題與參賽方向

銀行資料與開發團隊維護報表、資料流程與 SQL 腳本。欄位定義改動時，審查者需要追查下游 SQL、欄位與報表，並整理測試與上線前檢查。分散的腳本與人工追查使結果較難以一致格式交接。

參賽方向是「用 M365 Copilot 加速 SQL 變更影響評估，並保留銀行資料安全與人工覆核」。SQL 靜態分析提供可追溯的影響候選清單；Copilot 協助把清單整理為易讀摘要與待辦。工程師負責判斷、補查及正式變更審查。

## 方案與展示流程

1. 載入合成 SQL 變更前後版本及相關下游 SQL。
2. 使用 SQL SPA Tools 比對 SQL，分析來源與下游欄位關係。
3. 檢視 Copilot 摘要預覽，確認物件及欄位名稱可用於展示，且未包含原始 SQL、運算式或其他不應上傳內容。
4. 使用者確認後下載 JSON，手動上傳至 M365 Copilot Chat，並貼上固定提示。
5. 工程師將 Copilot 回答逐項對照 JSON 證據，確認影響、警告、限制及測試檢核項目。

若分析含解析警告，流程須保留警告及限制。無法找到下游關係不代表已證明沒有影響；未載入的程序、排程、動態 SQL 與外部報表不在靜態分析可保證的範圍內。

## 原型現況

| 項目 | 現況 | 可支持的說法 |
|---|---|---|
| 摘要匯出 | 已實作變更欄位輸入、來源標記、影響篩選及雙重確認 | 本機瀏覽器演練顯示 impacts 僅保留與變更來源欄位相符的兩項下游關係；工具仍未自行驗證 SQL 差異 |
| 資料最小化 | 匯出不含原始 SQL、運算式、檔名或錯誤訊息全文 | 交給 Copilot 的內容比原始 SQL 少；使用者仍須檢查名稱是否含敏感資訊 |
| 正常合成案例 | 已建立固定 SQL 與預期影響清單，並在本機瀏覽器跑過下游分析 | 結果符合兩個預期下游欄位：`DEMO_MONTHLY_REPORT.SEGMENT_LABEL`、`DEMO_RISK_SEGMENTATION.RISK_BUCKET`；其他 `CUSTOMER_ID` 關係不會列入此欄位變更的 impacts |
| 解析警告案例 | 已建立缺少 PIVOT `IN` 清單的案例 | 可檢查摘要是否帶出一筆警告及分析限制 |
| 自動化檢查 | 2026-10-23 Colab `full` 執行有 30 項通過：10 項 Node 契約、12 頁瀏覽器載入、4 項主要功能操作及 4 項個資檢查；另產生 1,000 筆 `prepared` 案例 | 1,000 筆尚未逐筆執行；瀏覽器流程未涵蓋所有選項與錯誤路徑；個資指標僅為 UTF-8 合成資料；不等同 M365 驗收 |
| M365 Copilot Chat | 個人帳戶臨時聊天已做三種文字探索案例；銀行核准租用戶及附件上傳未驗收 | 正常、解析警告與缺少 schemaVersion 的回覆符合提示規則；無逐字輸出保存、獨立對話重跑或配對耗時證據 |
| 效益比較 | 已定義配對量測計畫，尚無實測紀錄 | 目前不能報告節省時間、命中率或 Copilot 證據一致性數值 |

目前匯出 JSON 包含 `schemaVersion`、`generatedAt`、`source`、`changeSummary`、`changes`、`impacts`、`analysisMessages` 與 `limitations`。使用者可在摘要視窗輸入根據 SQL Compare 人工核對的變更物件、欄位及前後型別。JSON 以 `origin: operator_entered` 及 `verification: not_verified_by_tool` 標記來源；工具本身沒有解析 SQL Compare 的差異。當 `changes` 有資料時，匯出只保留來源物件與欄位相符的下游關係，並在 `limitations` 說明篩選範圍。若有輸入變更資訊，下載前須確認已人工核對；所有匯出仍須檢查物件名稱是否可提供。

## Colab 技術回歸與效能微基準

Colab `full` 模式驗證工具層的 Node 契約、頁面載入、主要操作及個資處理。這次執行的 30 項檢查均通過；另生成的 1,000 筆固定種子案例尚未逐筆執行，不計入通過數。個資指標在 UTF-8 合成檔案的命中類型與位元組區間比對中記錄 TP 450、FP/FN 0，Precision、Recall 與 F1 為 1.0；這不代表其他編碼或真實資料的辨識效果。完整逐項記錄見[成效驗證計畫與紀錄](成效驗證計畫與紀錄.md)及[Colab 測試報告](../test-results/test-report.xlsx)。

同次執行另以 100、1,000、10,000 筆 SQL 各跑 5 次 Oracle SQL Formatter `formatText` 微基準，P50 分別為 13.3、94.8、501.6 ms。此數據僅反映當次 Colab 環境中的格式化函式，不代表其他模組、端到端完成時間或人工節省。測試未連 Oracle；瀏覽器流程也未覆蓋所有操作及錯誤路徑。Colab 測試不呼叫 M365 Copilot Chat，亦不取代銀行租用戶回答品質驗收或人工／原型配對量測。

## 資料安全與責任邊界

展示一律使用合成 SQL、合成欄位及合成物件名稱，不使用銀行生產資料或真實客戶資料。原始 SQL 在設計流程中留在本機瀏覽器；使用者以明確操作匯出最小 JSON，再由使用者手動上傳。摘要雖移除 SQL 內容，仍可能包含物件與欄位識別名稱，因此不能假定所有內部名稱都可上傳。

上傳前由操作者檢查檔案及名稱，確認未包含帳號、身分證字號、金融識別資訊、密碼、連線字串、個人資料、未核准路徑或銀行機密。若無法判斷資料分類，先停止上傳並依銀行資料治理流程確認。Copilot 輸出只供工程師參考，不執行 SQL、不修改原始檔、不核准變更，也不觸發部署。

正式使用前，須由銀行資料治理與資訊安全確認可上傳資料範圍、核准租用戶、DLP、保存及稽核設定。以上項目尚未確認，不代表已取得正式環境核准。

## 效益驗證計畫

以固定合成案例比較人工流程與原型流程，各完成至少三次配對試次。依既有計畫記錄開始與結束時間、操作步驟、影響清單命中與漏列、誤列、Copilot 證據一致性及警告情境的不確定性表達。量測口徑與空白紀錄表已整理於[成效驗證計畫與紀錄](成效驗證計畫與紀錄.md)。

評估涵蓋四項：完成時間與操作步驟、影響清單完整度與正確性、回答是否能追溯 JSON 證據，以及警告案例下的限制揭露與重複性。另設資料安全門檻。實測前不設定或宣稱節省百分比；單一合成案例的結果也不推論為全行效益。

## 主要風險與處理方式

| 風險 | 展示中的處理 |
|---|---|
| 靜態解析未覆蓋外部或動態相依 | 明列載入範圍、警告與限制，由工程師補查 |
| Copilot 誤列、漏列或增加無證據推論 | 要求依 JSON 列證據；逐項人工核對，記錄錯誤 |
| 物件名稱本身屬內部敏感資訊 | 使用合成名稱；每次上傳前由操作者檢查 |
| M365 上傳或檔案讀取失敗 | 保留本機分析結果與匯出檔，記錄失敗流程 |
| 評估偏差或數據不足 | 固定案例與步驟定義，完成至少三組配對紀錄再報告 |
| 操作者輸入的變更背景與 SQL 分析證據混淆 | JSON 明確標記輸入來源與未驗證狀態；固定提示要求分開呈現 |

## 後續工作與需確認事項

### 參賽規則

- 確認報名、作品提交期限、提交格式及必要文件。
- 確認簡報與 Demo 時長、隊伍人數限制及作品限制。
- 取得官方評分表，取代目前團隊自擬的建議評分規準。
- 確認現場 Copilot Chat 帳號可上傳 JSON、支援格式、檔案限制及網路條件。

### 銀行資料治理

- 確認除帳號及身分證字號外的禁止上傳資料類型。
- 確認資料檢查、移除或遮罩的責任與流程。
- 確認核准的租用戶與資料保存、DLP 及稽核設定。

### 原型驗收與提案材料

- 在銀行核准的 M365 環境以獨立對話及 JSON 附件實測固定提示與回答品質；目前的個人帳戶文字演練不作為租用戶驗收。
- 完成至少三組人工與原型流程配對試次，填入量測紀錄。
- 演練正常、缺資料、解析警告、上傳失敗及 Copilot 無法讀取檔案情境。
- 在 M365 Chat 演練中確認 Copilot 能區分操作者輸入的 `changes` 與 JSON `impacts` 證據。
- 撰寫三至五分鐘 Demo 腳本，並依官方規則完成提案簡報。

## 結語

目前已具備可供審閱的原型流程、摘要確認機制、合成正常案例與警告案例。下一個決策點是確認官方參賽要求及可用的 M365 測試環境；完成核准環境中的 Copilot 演練與配對量測後，才能以實測證據補上效益結論及簡報主張。

# SQL 變更影響評估：成效驗證計畫與紀錄

## 目的與證據界線

比較工程師人工追查與 SQL SPA Tools 加 M365 Copilot Chat 流程，在同一個合成欄位變更案例中整理下游影響的時間、步驟與結果品質。此計畫提供可重跑的驗收方式。目前只有個人帳戶臨時聊天中的合成 JSON 文字探索性演練，尚無銀行核准租用戶的 Copilot 實測，也未完成配對計時，因此不宣稱節省時間或準確率已達任何數值。

案例與預期答案以 [`copilot-impact-demo`](../sql-spa-tools-main/uat-fixtures/copilot-impact-demo/expected.json) 為準。輸入只含合成 SQL 與合成物件名稱，不含資料列。這是單一案例的原型驗證，不能代表所有 SQL、銀行正式環境或普遍導入效益。

## 起訖點與步驟計數

- **開始計時：** 參與者看到任務說明，並可取得三份固定輸入檔時。人工與原型流程都從乾淨工作狀態開始。
- **完成計時：** 參與者交付受影響物件與欄位、每項證據、限制／待確認事項，以及至少一項工程師檢核建議；評分者收到可保存的結果時停止。
- **耗時：** 使用同一計時器記錄總秒數；包含讀檔、工具操作、Copilot 等待及人工核對。另記錄 Copilot 等待秒數，方便解讀端到端時間。
- **主要步驟數：** 每完成一項需要作判斷並產生可交付內容的階段計 1 步，不計滑鼠點擊或按鍵。記錄實際步驟名稱，不預設哪種流程步驟較少。
- **額外協助：** 記錄提示、重試、工具錯誤、外部協助及中斷；有協助的試次保留紀錄並標示，不與無協助試次混為一談。

步驟字典固定如下；額外重試或回頭修正另加步並註記：

| 流程 | 一個主要步驟 |
| --- | --- |
| 人工 | 開啟並定位變更前後 DDL；確認變更欄位；搜尋下游 SQL；檢視語句並記錄證據；整理影響清單與檢核建議 |
| 原型 | 比較前後 DDL；載入下游 SQL 並分析；檢視影響結果；預覽摘要並確認／下載；上傳 JSON 並提交凍結提示；核對 Copilot 輸出、證據與檢核建議 |

## 指標定義與判讀

| 評分項目 | 計算與記錄 | 判讀限制／護欄 |
| --- | --- | --- |
| 完成時間與步驟（15 分） | 每次記總秒數、主要步驟數；配對呈現人工與原型差值。三次以上報中位數與範圍；若計算時間變化百分比，公式為 `(人工秒數－原型秒數) ÷ 人工秒數 × 100%`，且同時列出原始秒數；人工秒數為 0 時百分比記 N/A | 不預設節省目標；樣本少時只描述此案例與參與者，不外推整體效益 |
| 影響完整度與正確性（15 分） | 以 `object + column` 比較答案與預期集合。TP 為命中、FN 為漏列、FP 為誤列；Recall=`TP ÷ (TP+FN)`，Precision=`TP ÷ (TP+FP)`。分母為 0 時記 N/A。另記是否與預期集合完全相同 | 案例只有 2 個預期影響，每一項即代表 50 個百分點的 Recall；必須同列 TP/FN/FP，不單獨用百分比掩蓋樣本大小 |
| Copilot 證據一致性（10 分） | 對 Copilot 每一項影響主張，核對是否能在 JSON 找到相同物件／欄位與來源證據。支持率=`有正確 JSON 證據的影響主張 ÷ 全部影響主張`；另計無證據主張數與錯誤引用數 | 主張數為 0 時記 N/A；錯誤引用或虛構相依關係須逐項保留，不以平均數抵銷 |
| 不確定性與重現性（10 分） | 正常案例每次比較影響集合是否一致；缺資料／解析警告案例逐次標記 Copilot 是否指出證據不足、警告與靜態分析限制。報告成功次數／總次數及每次差異 | 缺資料／警告案例尚未完成前，不宣稱不確定性測試通過。分析無結果不代表無影響 |
| 資料安全門檻（不另加分） | 每次上傳前檢查 JSON，不含原始 SQL、解析訊息全文、檔案路徑、帳號、身分證字號或其他不允許資料；由操作者簽記 | 發現敏感資料或無法判斷資料性質時停止上傳，該次記為安全中止並修正輸入後重跑 |

## 建議驗收門檻

以下是原型 Demo 的團隊驗收門檻，不是主辦單位官方配分或正式環境標準：

1. 正常案例輸出與預期影響集合完全一致；所有影響均附可追溯證據。
2. Copilot 不得新增 JSON 中沒有證據的影響關係；如有，記為未通過並保留原始回答。
3. 缺資料／解析警告案例中，Copilot 必須指出不確定性與分析限制；在該案例完成前此門檻標示「未測」。
4. 上傳前資料檢查必須通過；否則不進行上傳。
5. 時間與步驟只報實測分布，不設定尚無基準支持的節省率承諾。

# Google Colab 自動化測試框架需求摘要

## 一、目標

建立可在 Google Colab 一次執行的測試框架，使用合成資料驗證 SQL SPA Tools，並自動產生 Excel 報告與黑客松簡報所需的統計圖表。

本文件為已確認方向的需求與實作計畫摘要，不代表框架已完成或已有實測成果。

## 二、測試範圍

1. 產生 1,000 組可重現的 Oracle SQL 合成案例，涵蓋基礎查詢、JOIN、子查詢、CTE、血緣、Oracle 特有語法、DDL／DML、個資與錯誤輸入。
2. 驗證全部 12 個工具頁、Copilot 摘要匯出及共用介面。
3. 同時驗證核心處理結果與主要瀏覽器操作、持久化及匯出流程。
4. 測試個資辨識、畫面遮罩、檔案清除及正常內容保留，統計 Precision、Recall、F1、誤判與漏判。
5. 量測大量 SQL 的工具處理耗時與吞吐量，不連線 Oracle 資料庫。

### 合成案例配置

| 主類別 | 數量 | 主要內容 |
|---|---:|---|
| 基礎查詢 | 150 | 篩選、排序、NULL、字串與日期 |
| JOIN 與子查詢 | 150 | 多表關聯、別名、巢狀查詢 |
| CTE 與血緣 | 150 | 多層 CTE、直接與間接欄位來源 |
| Oracle 特有語法 | 150 | 分析函數、MERGE、階層查詢、PL/SQL |
| DDL／DML 與版本差異 | 150 | 建表、異動、型別與欄位變更 |
| 個資與正常資料對照 | 150 | 合成個資、近似格式、檢查碼與日期 |
| 邊界與錯誤輸入 | 100 | 空白、註解、引號、截斷、不支援語法 |
| **合計** | **1,000** | |

每案可包含 SQL、比較版本、CSV、預期結果與個資位置標註，並明列適用模組及預期行為。壓力測試衍生資料獨立計數，不冒充新增的獨立案例。

### 模組驗證內容

| 模組群組 | 核心驗證 |
|---|---|
| Formatter、Compare | 格式化穩定性、字串與註解保留、差異與忽略選項 |
| Catalog、SQLScriptManage | 清冊、搜尋、版本、備份與還原 |
| 欄位血緣、Copilot 摘要 | 來源與影響集合、解析警告、摘要內容與確認程序 |
| Excel／CSV 轉 SQL、CTE | 型別、NULL、跳脫、前導零及 Oracle 輸出 |
| 欄位映射、SQL Lab | 映射產物、查詢結果、工作區隔離與持久化 |
| 品質稽核、關聯探索 | 已知異常、品質計數、預設關聯與分析輸出 |
| 個資清除器 | 辨識、清除、非命中內容保留與匯出 |
| 共用介面 | 載入、導航、主題、主要操作與下載 |

## 三、技術架構

- Python：統籌執行、生成資料、彙整結果及製作報告。
- Node.js 22：執行既有回歸測試及核心功能測試。
- Playwright Chromium：操作實際工具頁面，驗證主要流程、Worker、IndexedDB 與匯出內容。
- 預設亂數種子為 `20261023`；預期答案由案例模板與獨立標註產生，不呼叫受測工具產生答案。
- 支援上傳專案 ZIP，或指定 Git 倉儲與版本；預設使用 ZIP，不要求公開倉儲或帳號憑證。
- 提供快速驗證與完整執行模式；完整模式使用全部 1,000 案例。
- Notebook 依序執行環境檢查、依賴安裝、資料生成、功能測試、個資測試、效能測試、報告與下載。
- 每次記錄種子、來源版本或檔案雜湊、套件版本、執行環境、時間及設定，並逐案保存結果。
- 不變更產品公開介面；透過測試轉接層呼叫現有程式，避免另寫一套業務邏輯代替受測實作。

## 四、個資與效能測試

### 個資準確性

- 涵蓋身分證、新式居留證、帳號、統編、彙整序號及子號。
- 測試檢查碼切換、日期／時間排除、重疊命中，以及 UTF-8、Big5、UTF-16 編碼。
- 依「類別＋位元組範圍」比對標註，計算 TP、FP、FN、Precision、Recall、F1；分母為零標記 N/A。
- 驗證刪除後無預期個資殘留，且非命中位元組保持不變。
- 分開檢查畫面遮罩與檔案清除，並保留正常數字與帳號格式無法僅靠規則區分時的誤判結果。

### 大量資料效能

- 格式化、比對、血緣、清冊與個資掃描的 SQL 壓力規模為 100、1,000、10,000 份。
- 表格工具另測 1,000、10,000、100,000 列合成資料。
- 每項暖機一次、正式量測五次，記錄輸入大小、耗時、吞吐量、成功數及逾時。
- 依逐案耗時提供 P50／P95；分開記錄引擎處理與主要操作的端到端耗時，不混入依賴安裝與啟動時間。
- 預設單次壓力測試上限 120 秒；失敗或逾時後仍保存結果並繼續。
- 先建立效能基準，不預設未經量測的通過門檻。報告附執行環境，避免將不同 Colab 資源條件直接比較。

## 五、交付內容與位置

所有框架檔案位於專案根目錄的 `colab/` 下：

```text
colab/
├─ rfp.md                          # 本需求摘要
├─ sql_tools_test_framework.ipynb   # Colab 執行入口
├─ testing/                        # 測試、資料產生、報告與圖表程式
├─ docs/
│  └─ testing-guide.md             # 操作與故障排除說明
└─ outputs/
   └─ <執行時間與識別碼>/
      ├─ test-report.xlsx
      ├─ charts/
      ├─ fixtures/
      ├─ results/
      └─ test-results.zip
```

每次成果包含：

- `test-report.xlsx`：總覽、模組覆蓋、案例明細、個資指標、效能結果、失敗與限制、執行資訊。提供篩選、凍結標題、狀態文字及適當數字格式。
- `charts/`：案例分布、模組測試狀態、個資 Precision／Recall、誤判與漏判、規模與耗時、吞吐量的 PNG／SVG 圖表；標明樣本數、單位及測試版本。
- `fixtures/`：合成案例與預期答案。
- `results/`：JSON／CSV 原始測試結果、執行摘要及證據。
- `test-results.zip`：完整下載包。

Excel 與圖表遵循根目錄 `theme.md` 的石墨與冰藍企業配色。保留既有 `colab/docs/setup.md` 及 `colab/close_colab_sessions.py`。

Colab 執行成果先存於雲端工作階段，不會自動寫回本機 D 槽；下載後可解壓至本機 `colab/outputs/`。

## 六、結果契約與驗收標準

- 統一結果包含執行 ID、案例 ID、模組、測試層級、預期值、實際值、狀態、耗時、錯誤及證據位置。
- 相同種子可產生相同的 1,000 組主案例。
- 所有工具模組均有核心結果與主要流程驗證。
- 預期答案不得由受測工具自行產生。
- 通過、失敗、執行錯誤、跳過及待人工驗收分開呈現。
- 跳過項目不得計入通過數；所有比例須標示分母。
- 測試失敗或逾時仍可輸出報告。
- 以已知 TP／FP／FN 案例驗證統計公式。
- Excel、圖表與原始結果一致，繁體中文正確顯示。
- 在乾淨 Colab CPU 環境完成一次完整執行與下載驗證；未完成實跑不得標示已驗收。
- 同步維護新增測試涉及的 CI、驗證命令及操作文件。

## 七、界線與限制

- 僅使用合成資料，不使用銀行正式資料或真實客戶資料。
- SQL Lab 使用另附的相容資料與查詢，依其支援的引擎測試，不視為 Oracle 執行環境。
- 原生資料夾授權以可控檔案介面測試資料處理，另列人工驗收，不以模擬結果代替實際權限驗收。
- 不自動操作 M365 Copilot，不將工具效能推算為人工節省工時或 Copilot 成效。
- 產生簡報所需圖表，不自動修改既有成果簡報。
- 發現產品缺陷時保留失敗證據，另列修正事項，不以調整預期答案掩蓋問題。

# SQL 變更影響評估 Copilot Demo 講稿

## 使用方式

本講稿配合「SQL變更影響評估Copilot_提案簡報.pptx」，預估 4 分 30 秒。已在個人帳戶的臨時聊天以合成 JSON 做正常、警告及缺欄文字探索；銀行核准租用戶與 JSON 附件尚未驗收。Copilot 畫面段落仍是流程腳本，不能當作銀行環境測試結果。

## Demo 前準備

- 使用 `sql-spa-tools-main/uat-fixtures/copilot-impact-demo/` 內的合成 SQL 與預期結果。
- 在瀏覽器開啟 SQL Compare 及 SQL 欄位血緣分析器，確認載入的是 `customer-before.sql`、`customer-after.sql`、`downstream.sql`。
- 準備解析警告案例 `parser-warning.sql`，以及 Copilot Chat 固定提示。
- 若測試租用戶已核准且可用，準備清空的 Copilot Chat 對話及剛匯出的合成 JSON；上傳前檢查檔案。若銀行核准環境不可用，就展示本機分析與提示稿，明確說明目前只有個人帳戶探索性文字演練，銀行租用戶與附件流程尚未驗收。
- 不使用真實銀行 SQL、客戶資料或內部物件名稱。

## 逐段講稿

### 0:00–0:25｜問題與目的

「銀行資料流程中的 SQL 欄位一旦改動，工程師要追查哪些報表和下游欄位可能受影響，並把依據及測試項目交給審查者。本原型使用 SQL SPA Tools 做靜態差異與欄位血緣分析，再讓 M365 Copilot Chat 協助整理文字；最後仍由工程師核對。」

### 0:25–0:55｜資料流程

「原始 SQL 在本機瀏覽器分析。工具先產生摘要預覽，操作者檢查內容後才確認下載 JSON，再手動交給 Copilot Chat。Copilot 不會連資料庫，也不會執行 SQL、批准變更或觸發部署。若上傳內容或資料分類不清楚，就停止交接。」

### 0:55–1:50｜正常案例操作

「這是合成欄位 `DEMO_CUSTOMER.CUSTOMER_SEGMENT`，定義從 `VARCHAR2(20)` 改成 `VARCHAR2(40)`。SQL Compare 結構摘要顯示一項欄位定義修改。載入下游 SQL 後，欄位對照表會看到四筆關係，其中兩筆屬於未變更的 `CUSTOMER_ID`。固定案例的預期影響只有 `DEMO_MONTHLY_REPORT.SEGMENT_LABEL` 和 `DEMO_RISK_SEGMENTATION.RISK_BUCKET`，一項直接、一項間接。」

### 1:50–2:30｜摘要確認及 Copilot 整理

「接著開啟 Copilot 摘要預覽，依 SQL Compare 人工核對結果輸入變更物件、欄位和前後型別。JSON 將這項資料標記為 `operator_entered`，並標明工具未驗證 SQL 差異。輸入欄位後，`impacts` 只保留來源物件與欄位相符的兩項下游關係。摘要移除 SQL、運算式、路徑及錯誤訊息全文，但仍包含物件與欄位名稱，所以操作者還要檢查名稱是否能上傳，並分別確認變更資訊和資料內容。個人帳戶臨時聊天的探索性回覆有列出兩項預期影響、標示操作者輸入且工具未驗證，並保留分析限制；這不是銀行租用戶驗收，也不代表回答品質已通過正式驗收。」

### 2:30–3:05｜解析警告情境

「再看警告案例：輸入故意省略 PIVOT 的 `IN` 清單。工具摘要應保留一筆解析警告。若 Copilot 回答未指出警告或把沒有找到的關係說成沒有影響，就記為未通過並由工程師補查。靜態分析的範圍也不包含未載入的程序、排程或外部報表。」

### 3:05–3:50｜效益驗證

「我們不預先承諾節省比例。驗證計畫用相同案例比較人工流程與原型流程，至少做三組配對試次，記錄完成時間、步驟數、影響命中、漏列、誤列、Copilot 證據一致性，以及警告是否被揭露。現在紀錄表仍是空白，所以沒有可報告的實測效益。」

### 3:50–4:30｜下一步與結尾

「目前已完成摘要預覽與確認、正常合成案例、預期清單及警告案例。下一步是在核准的 M365 環境完成端到端演練與配對量測，同時確認官方提交格式、評分規則及資料上傳要求。今天展示的是可檢查的原型流程，並非正式環境核准或效益結論。」
